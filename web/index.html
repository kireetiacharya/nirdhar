NirdharAI-powered digital property valuation · Pune first · Hyderabad next
Prototype. Pune uses real OpenStreetMap locations, metro stations, amenities and river proximity, plus real Makaan rents. Transactions are still synthetic (structured like Index-II) until the e-Search sample arrives, so values and grades illustrate the method, not real valuations.

Value a flat the way an expert valuer does

Pick a demo scenario or enter a property. Nirdhar returns a deed-calibrated value, a calibrated 90% range, the comparables it used, the reasons in rupees, and the lending route.

1 · Three prices reconciledAsking, registered and guidance values modelled per micro-market.
2 · Three models, stackedGradient boosting, comparable-sales attention and a hierarchical hedonic model.
3 · Confidence decides the routeSpatial conformal range → grade A–D → desktop, light-touch or field visit.

Valuation API

Five fields are enough: micro-market, project, BHK, area and floor. Everything else is looked up from the precomputed feature store.

POST /api/valuations
{
  "city": "Pune", "micro_market": "Yerawada", "project_id": "PUN-0123",
  "bhk": 2, "carpet_area": 850, "floor": 7,
  "agreement_value": 8200000, "loan_amount": 6000000        // optional
}

POST /api/valuations   (commercial: income approach)
{ "city": "Pune", "micro_market": "Kothrud", "property_type": "commercial",
  "commercial_kind": "shop", "bhk": 1, "carpet_area": 420, "floor": 0
}

→ value_inr, p05_inr, p95_inr, grade, drivers (₹), comparables (attention weights),
  reconciliation, project_intel, flags, route, data_quality, model_version, data_snapshot_hash

GET  /api/valuations/{id}            stored valuation (audit store)
POST /api/valuations/{id}/replay     re-run with the same inputs and verify an exact match
GET  /api/model                      model card: metrics, ablation ladder, pipeline report
GET  /docs                           interactive OpenAPI docs
